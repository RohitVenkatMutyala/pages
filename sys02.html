sys 02: load balancing algorithms

1. Round Robin

When to use: Simple clusters where all servers have identical hardware.

The Load Balancer acts like a card dealer, distributing requests sequentially.

  • How it works: Request 1 goes to Server 1, Request 2 to Server 2, Request 3 to Server 3, and then it loops back to Server 1.
  • The Flaw: It assumes all requests take the same amount of time. If Server 1 gets a heavy video-processing request, and Server 2 gets a tiny text request, Round Robin will still blindly send the next request to Server 1, potentially overloading it.

2. Least Connections

When to use: Heavy applications where requests take a long, variable amount of time.

The Load Balancer actively monitors the real-time queue length of every server.

  • How it works: Before routing a packet, the LB scans all servers. It finds the server currently processing the fewest number of active connections and routes the new packet there.
  • The Benefit: It perfectly balances the load, naturally avoiding servers that are bogged down with heavy computations.

3. IP Hashing (Sticky Sessions)

When to use: Stateful applications (e.g., E-commerce shopping carts).

A mathematical guarantee that a user will always return to the same server.

  • How it works: The LB takes the Client's IP address (e.g., `192.168.1.5`) and runs it through a hash function (like Modulo math). The result determines the server.
  • The Benefit: Client A will always be routed to Server 1. Client B will always be routed to Server 2. If Server 1 holds Client A's un-saved shopping cart data in RAM, this ensures they don't suddenly hit Server 2 and find an empty cart.
