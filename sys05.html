sys 05: edge & api management

1. CDN (Content Delivery Network)

Static assets belong at the Edge, not in your database.

  • Images, Videos, and CSS files rarely change. Serving them from your central backend is slow and wastes bandwidth.
  • A CDN copies these static files to "Edge Servers" all over the globe. When a user requests an image, they download it from a server physically close to them, bypassing your backend entirely. (Result: ~15ms latency).

2. The API Gateway

The bouncer at the front door of your dynamic microservices.

  • Dynamic requests (like POST /login or GET /bank-balance) cannot be cached globally. They must hit your backend.
  • Instead of exposing your backend directly to the internet, you use an API Gateway. It handles routing, verifies JWT Authentication tokens, and acts as a shield.

3. Rate Limiting (Token Bucket)

Protecting the system from DDoS and abusive scraping.

  • We use algorithms like the Token Bucket. The bucket holds a maximum number of "tokens" and refills at a steady rate.
  • Every API request costs 1 token. If the bucket is empty, the API Gateway drops the request and returns a 429 Too Many Requests error, saving the backend from crashing.
